# Cortex — spec

One local app that is the whole second brain: notes (markdown + LaTeX), a PDF library, projects, a daily page, and a chat that reads and writes all of it. Data is plain files in a vault so any agent (Claude Code, Codex, OpenCode) can work on the same files. No Notion, no external database.

## Vault (plain files)

Default `~/Cortex`, override with `CORTEX_VAULT`.

```
notes/<slug>.md          frontmatter: title, kind (fleeting|literature|permanent|meeting|daily),
                         topics: [slug], sources: [library id], projects: [slug], created, updated
daily/YYYY-MM-DD.md      same shape, kind: daily
projects/<slug>.md       frontmatter: title, status (active|paused|done|banked|refuted),
                         type (research|competition|build|career|life), verdict, next_action,
                         deadline, repo, topics; body = free notes
library/<id>/paper.pdf   the PDF (id = arXiv id if known, else slug)
library/<id>/meta.json   {id,title,authors,year,arxiv,link,type,status,rating,takeaway,topics,added,pages,source_path}
library/<id>/notes.md    optional reading notes (markdown + LaTeX)
library/<id>/text.txt    extracted text (generated by the server, used for search)
topics.json              [{slug,name,kind,one_liner}]
chats/<channel>.jsonl    one JSON message per line: {id,role,content,ts,trace:[...]}
.cortex/index.sqlite     FTS5 search index (generated, gitignored)
```

Markdown everywhere. Inline math `$...$`, display math `$$...$$`, rendered with KaTeX.

## Server (FastAPI, Python 3.11, port 8788)

Run: `cd cortex && uv run --with fastapi,uvicorn,openai,pypdf,python-frontmatter,python-multipart uvicorn server.app:app --port 8788`
(or `python3.11 -m uvicorn server.app:app --port 8788` once deps are installed). Serves the built frontend from `web/dist` at `/`.

```
GET  /api/health                      {ok, vault, counts}
GET  /api/topics                      [topic]

GET  /api/notes?kind=&q=&limit=       [{slug, title, kind, topics, updated, preview}]
POST /api/notes                       {title, kind?, body?, topics?} -> note
GET  /api/notes/{slug}                {slug, frontmatter, body}
PUT  /api/notes/{slug}                {frontmatter?, body?} -> note   (server sets updated)
DELETE /api/notes/{slug}
GET  /api/daily/today                 note (created if missing)

GET  /api/projects?status=            [project]  (project = {slug, frontmatter, body})
GET  /api/projects/{slug}
PUT  /api/projects/{slug}             {frontmatter?, body?}
POST /api/projects                    {title, ...frontmatter}

GET  /api/library?status=&topic=&q=   [meta]
GET  /api/library/{id}                {meta, notes, text_preview}
PUT  /api/library/{id}                partial meta (status, rating, takeaway, topics, title, ...) and/or {notes}
GET  /api/library/{id}/pdf            application/pdf (inline)
POST /api/library/ingest              {path} | {arxiv} | {url}  -> meta   (copies/downloads the PDF, extracts text, indexes)
POST /api/library/upload              multipart file -> meta

GET  /api/search?q=&limit=            [{type: note|project|paper, id, title, snippet, score}]

GET  /api/chat/channels               [{id, name, desc, count}]
GET  /api/chat/{channel}              [message]
DELETE /api/chat/{channel}
POST /api/chat/{channel}              {content, model?}  -> text/event-stream
      events (JSON per `data:` line):
        {type:"text",  delta}
        {type:"tool",  id, name, input, status: "running"|"ok"|"error", summary?, link?}
        {type:"done",  message}      message = the stored assistant message (with trace)
        {type:"error", code, message}
GET  /api/models                      [{id, name}]  (cached from the provider)

GET  /api/agents                      [{id: codex|opencode|claude, available: bool, version}]
POST /api/agents/run                  {agent, task} -> text/event-stream of {type:"log",line} … {type:"done",code}
```

### Chat provider

OpenAI-compatible. Default provider **OpenCode Go**: base `https://opencode.ai/zen/go/v1`, key from `OPENCODE_API_KEY` or `~/.local/share/opencode/auth.json` (`opencode-go.key`). Default model `glm-5.3` (`glm-5.3-flash` for quick), switchable per message. Any other OpenAI-compatible provider via `CORTEX_BASE_URL` + `CORTEX_API_KEY`.

Tools the model gets (all run server-side against the vault): `search_vault(query, scope)`, `read_note(slug)`, `write_note(title, kind, body, topics)`, `append_daily(text)`, `read_paper(id, section?)`, `file_paper(arxiv|url|path, takeaway?)`, `set_paper(id, status?, rating?, takeaway?)`, `list_projects(status)`, `update_project(slug, verdict?, next_action?, status?)`, `run_agent(agent, task)` (spawns the CLI in the vault, bounded output). Every tool call is streamed to the UI as a ledger row.

System prompt: research partner inside Ajinkya's brain; ground answers in the vault (search first); write only when asked; cite notes/papers by title with app links `cortex://note/<slug>`, `cortex://paper/<id>`, `cortex://project/<slug>`.

## Web (Vite + React + TypeScript, `cortex/web`)

Three panes. Left rail 250px: search field (Cmd+K palette), then sections — Daily (today), Notes (grouped by kind, most recent first), Library (Inbox / Reading / Read / Reference counts), Projects (by status), Topics. Center: the open thing. Right 380px, collapsible: chat.

- **Note view**: CodeMirror 6 markdown editor left, live preview right (markdown-it + markdown-it-katex or katex auto-render); toggle editor-only / split / preview-only. Autosave 800 ms after typing stops. Frontmatter editable in a slim header strip (title, kind, topics chips).
- **Paper view**: PDF in an `<iframe src="/api/library/{id}/pdf">` filling the center; a slim right-hand meta strip inside the center pane (status select, 1–5 rating, takeaway textarea, topics chips, link, authors, year) and a "Notes" tab that opens `notes.md` in the same editor.
- **Project view**: frontmatter as a compact form (status, type, verdict, next action, deadline, repo), body editor below.
- **Chat**: channels as tabs (general, papers, projects, ideas, daily); streaming reply; a ledger under each reply listing tool calls (verb + what, linked); model picker; Stop; "hand to Codex" / "hand to OpenCode" buttons that call `/api/agents/run` and stream the log into the panel. `cortex://` links in replies open the target in the center pane.
- **Search palette**: Cmd+K, results grouped by type, Enter opens.

Design: same identity as the published Cortex artifact — verdigris accent `#2F8F7B` (dark `#4DB39D`), cool green-grey neutrals, `Bricolage Grotesque` for headings and channel names, `IBM Plex Sans` body, `IBM Plex Mono` for meta and the ledger. Light and dark via `prefers-color-scheme` plus a manual toggle. No emoji as UI, no gradients, no purple.

## Import (scripts/import_local.py)

Builds the initial vault from local data, without Notion: papers from `queue.json` (the triaged PDF list with arXiv metadata), notes from the Bear export, projects and topics from the seed list in the script. Idempotent.
